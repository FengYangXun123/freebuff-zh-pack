# freebuff-zh-pack — Freebuff Desktop 简体中文汉化包

非官方的 Freebuff Desktop 中文界面补丁。运行时注入，不改服务端数据、不访问网络（唯一例外：可选的「检查更新」，可 `--no-net` 关闭）、可完整还原。

> 当前适配：**Freebuff Desktop 0.0.205**（Windows x64）· 兼容矩阵见 `manifests/compat-matrix.md` · 无自动推送，请 Star 收 Release 通知

## 它做什么

Freebuff Desktop 的主界面来自远端 freebuff.com 网页，官方目前没有任何中文通道（`og:locale` 仍为 `en_US`）。本包在本地壳的 `app.asar` 内注入一个运行时翻译层，把界面文案实时替换为中文——

- **5,832 条词典**：自建 3,946 条（`zh-main` 1184 + `zh-remote` 2762，主界面 / 设置 / 用量 / 模板分类全覆盖），并接入社区项目 [Kfowever/freebuff-zh-patch](https://github.com/Kfowever/freebuff-zh-patch) 的 3,164 条词库与 200+ 条正则规则（MIT，许可随附 `licenses/`）；三库合并去重后 5,832 条
- **双层注入共用同一词典**：本包译文优先、社区层兜底，两层同源，避免 React 重绘时互相覆盖
- **聊天内容零接触**：只处理界面属性与文案节点，用户输入、对话正文、代码块物理隔离

## 三道防线（本包与同类补丁的主要差异）

| 防线 | 防什么 | 说明 |
|---|---|---|
| **熔线预检** | 上游开启 asar 完整性校验 | 安装前读取主程序内嵌的 Electron 熔线位，若校验已开启**拒绝安装**——强行注入会导致应用无法启动 |
| **运行时自检** | 注入脚本静默失效 | 注入层在写入前经 Node 运行时 DOM stub 实跑；语法正确但运行报错（界面全英文的典型成因）会在安装时当场暴露 |
| **基线核验** | 基线污染 / 半汉化状态 | 首次安装自动备份官方原版（`.zhorig`）；还原按基线整字节恢复并校验哈希；已汉化但无基线的异常态会被拒绝处理 |

## 安装（Windows x64）

1. 到 [Releases](../../releases) 下载最新 `freebuff-zh-pack-vX.Y.Z.zip`，解压到任意目录
2. **彻底退出 Freebuff**（含托盘）
3. 双击 `安装.cmd`，按菜单操作：`1` 安装/重装 · `2` 查看状态 · `3` 检查更新 · `4` 还原英文原版
4. 安装器自动定位安装目录（也可用 `--path` 或环境变量 `FREEBUFF_PATH` 指定）
5. 启动 Freebuff，主界面即中文

**依赖**：Python 3.9+（官网版/商店版均可，`安装.cmd` 自动探测并做真实性校验）与 Node.js 18+（运行时自检闸门用）。两者都只需装好即在 PATH；`FREEBUFF_PYTHON` 环境变量可显式指定解释器（含空格路径亦可，会自动转短路径）。

命令行直接调用（适合自动化）：

```bash
python install.py --install          # 安装（幂等）
python install.py --status           # 状态盘点（含熔线与指纹）
python install.py --check-update     # 查上游最新版本（--no-net 跳过联网）
python install.py --restore          # 还原英文原版
python install.py --install --force  # 跳过版本警告（熔线/架构硬拦仍生效）
```

**退出码**：`0` 成功 · `2` 未找到安装目录/用法错误 · `3` Freebuff 运行中 · `4` 熔线拦截 · `5` 架构异常 · `6` 基线冲突 · `7` 引擎失败 · `8` 缺 Node.js · `10` 用户取消。

两条硬性拦截（不提供「继续」选项）：检测到上游**开启 asar 完整性校验**、或**架构特征异常**（`resources/orchestrator` 缺失）时，安装器直接拒绝——这类情况下强行注入会导致白屏，请等待本包适配。

说明：界面文案同时来自本地壳与 freebuff.com 远端页面，两者**更新节奏不同步**。远端文案变更后词典可能滞后（表现为个别英文残留，服务端广告位与活动串属于此类且随时序随机），一般数日内随本包更新补齐；个别串重启应用即译。

## 常见问题

**Q1：安装后界面还是英文？**
先跑 `安装.cmd` 菜单 `2` 查看状态：若显示「已注入」，说明是远端新文案尚未进词典或动态串晚于注入到达——重启应用再看，仍残留请开 Issue 附截图；若显示「未注入」，把状态页完整输出贴进 Issue。

**Q2：Freebuff 自动更新后变回英文了？**
正常现象，官方更新会覆盖 `app.asar`。重新运行 `安装.cmd` 即可：安装器会按新版本重建基线（实测上游更新会清掉旧基线；若残留旧版基线，安装器检测到版本不一致也会自动重建）并提示版本兼容状态。

**Q3：如何彻底还原英文原版？**
菜单 `4`。按首次安装时的字节级基线恢复并校验哈希，基线随后清理，与手工覆盖 `app.asar.zhorig` 等效。

**Q4：会封号 / 影响账号吗？**
本包不访问网络（「检查更新」为可选的一次只读请求，可用 `--no-net` 关闭）、不上传数据、不修改任何服务端数据，与账号体系零交互；汉化原理与浏览器翻译插件同源。但**使用行为层面的风险始终由上游政策决定**，与本包无关。

**Q5：支持 macOS / Linux 吗？**
官方有 mac/Linux 版，但本包未适配（未实测不发布）。`install.py` 的路径探测与引擎是平台无关设计，mac 适配待触发（见兼容矩阵）；有需求请到 Issue +1。

**Q6：为什么安装器要 Python 和 Node？**
汉化引擎需要安全解包/重打包 `app.asar` 并对注入脚本做运行时自检——这部分逻辑只有一份（Python 实现），我们不维护第二份等价实现以免行为漂移；Node 用于安装时的语法与运行时双闸门。两者均为免费软件，`安装.cmd` 会自动探测并指引。

## 已知限制

- Windows x64 实测可用；win-arm64 理论可用未验证；mac/Linux 未支持（见 Q5）
- 个别由后端服务下发的文案（广告位、活动串、邀请语时序竞态）不在稳定注入范围
- 无固定发版节奏、无 SLA——跟随上游更新触发，README 与 Release 永远标注当前适配版本
